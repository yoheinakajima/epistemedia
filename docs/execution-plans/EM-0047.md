# EM-0047 — Ordinary-PR attestation noise

## Goal

Make the trusted open-docket attestation workflow a clean no-op for ordinary pull requests without
making any docket-sensitive path easier to sign. Preserve the installed App as the only writer of
the protected check and retain exact-head binding before classification.

## Design

1. Fetch the current pull-request head and full changed-path list with the workflow's read-only
   token.
2. Compare the current head to the completed validation run's exact head before classifying paths.
3. Classify an all-ordinary path set as ineligible and exit successfully before the App-token step.
4. Treat every path under `research/open-dockets/` as sensitive. Such a change is eligible only
   when the complete PR diff is exactly the five required files for one direct docket directory.
5. Keep App-token creation and protected-check creation conditional on that exact eligible result.
6. Exercise ordinary, exact-promotion, malformed-promotion, submission, and mixed-path fixtures,
   then run the complete deterministic validation wall.

## Stop conditions

- Do not alter the required-check ruleset, App installation, App permissions, secret, or variable.
- Do not weaken accepted-base submission or promotion validation.
- Do not access a private key or token outside the existing trusted workflow.
- Do not modify accepted dockets, submission PRs, cases, evidence, policies, schemas, or receipts.
- Do not ready, merge, deploy, publish, admit, promote, delete a branch, or rewrite history.
