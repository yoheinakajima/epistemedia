# EM-0047 — Ordinary-PR attestation noise

## Goal

Make the trusted open-docket attestation workflow a clean no-op for ordinary pull requests without
making any docket-sensitive path easier to sign. Preserve the installed App as the only writer of
the protected check and retain exact-head binding before classification.

## Design

1. Bind the successful validation event to the canonical repository, its default-branch ref, exact
   base SHA, and exact head SHA. Require the live open pull request to match all four identities
   before classification.
2. Fetch the exact pull-request head without checking it out, then classify the immutable
   merge-base diff between those two commit identities. Disable rename detection so a move cannot
   hide a sensitive source path.
3. Classify an all-ordinary change set as ineligible and exit successfully before the App-token
   step.
4. Treat every path under `research/open-dockets/` as sensitive. Such a change is eligible only
   when the complete exact-SHA diff is five newly added files for one direct docket directory.
5. Keep App-token creation and protected-check creation conditional on that exact eligible result.
   Immediately before signing, require the PR to remain open at the same canonical repository,
   default-branch ref, validated base, and validated head.
6. Exercise ordinary, exact-promotion, rename, head-drift, base-retarget, malformed-promotion,
   submission, and mixed-path fixtures, then run the complete deterministic validation wall.

## Stop conditions

- Do not alter the required-check ruleset, App installation, App permissions, secret, or variable.
- Do not weaken accepted-base submission or promotion validation.
- Do not access a private key or token outside the existing trusted workflow.
- Do not modify accepted dockets, submission PRs, cases, evidence, policies, schemas, or receipts.
- Do not ready, merge, deploy, publish, admit, promote, delete a branch, or rewrite history.
