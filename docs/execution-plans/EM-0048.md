# EM-0048 - Philosophy inquiry application profile

## Goal

Implement a bounded, argument-agnostic adapter for importing and inspecting provenance-bearing philosophy inquiry bundles without changing accepted knowledge, normative schemas, disclosure policy, or public routes.

## Design

1. Define a strict application document in implementation code, reusing Epistemedia source, snapshot, span, proposition, assertion, derivation, evaluation, and projection concepts.
2. Validate exact fields, content hashes, referential closure, relation role distinctions, exposure lineage, evaluation frontiers, disclosure classes, and release state.
3. Canonicalize unordered collections and deduplicate byte-identical records by content identity; reject collisions and conflicting duplicates.
4. Build a private projection and a default-deny public projection. Prove disclosure noninterference by comparing every public surface after arbitrary private-only mutations.
5. Render Markdown and JSON twins, candidate-funnel summaries, trace records, and semantic branch diffs from the same projection.
6. Use only fictional fixtures. Run the complete deterministic repository check and record a proposal receipt.

## Stop conditions

- Do not modify constitution, policy, protocol schemas, accepted research, catalog, public site, CLI, server, release, or workflow files.
- Do not include unpublished arguments, real competition prompts, manuscripts, rankings, logs, or private-state-revealing digests.
- Do not merge, deploy, release, or admit the application profile.
